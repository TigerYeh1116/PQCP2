## 一、原來的半徑 4 並非所有合法三值候選的半徑 4

原 C 修復器的宣告正確，但有重要限定：**每側各符號個數固定**。
GPU 每個 lane 也只交換位置；內容可在重啟時更換，單次軌跡不能跨內容。
原題只要求三值 a,b 的指定總和、總平方和與相關方程，沒有指定各側零的個數。

令一側的符號 −1、0、+1 個數為 n,z,p，對應原 binary 偶、奇位 bit=1
個數為 e,o，長度 d=43。則

```
z=e+o−2n, p=d−e−o+n;
max(0,e+o−d) ≤ n ≤ min(e,o)。
```

上下界直接來自 n,z,p 非負，以及零對可分配至指定奇偶權重的條件。
兩側滿足 C(0)=d，又給出

```
n_A+n_B = (e_A+o_A+e_B+o_B−d)/2。
```

因此固定 target 下可行 n_A 是一個整數區間，n_B 由等式決定。
**只要各側新內容仍可行**，以下移動保持各側總和及兩側总平方和：

```
A: 00 → (+1,−1) 或 (−1,+1)
B: (+1,−1) 或 (−1,+1) → 00
```

也可反向。A 的 n 增 1，B 的 n 減 1；平方和分別增 2、減 2。
這不保證非零位移相關不變，必須精確計算新相關。

### 完整性：補齊半徑 4 的跨內容部分

固定長度與符號總和，內容變化必為 (Δn,Δz,Δp)=(t,−2t,t)。
總平方和固定強制 t_A+t_B=0。若 t 非零，每側至少改 2|t| 個位置。
總改動不超過 4 時，只能 t_A=±1、t_B=∓1，每側恰改兩個位置，
恰為上述 00/+- 轉換。因此原固定內容修復與此轉換搜尋的聯集，
就是**同一 target 奇偶權重下所有可行內容的 Hamming 半徑 4**。
不包含另一 target 的權重，也不證明更遠處無解。

### 連通性：為何應放入候選生成

交換可連通同一內容的所有排列。可行 n_A 是整數區間，每個相鄰值可由
一次合法上述轉換連接。因此「交換＋跨內容轉換」的無向可行狀態圖是連通的。
這是允許移動集合的性質；若接受規則只允許能量下降，實際可到達圖仍可能
不連通。退火溫度、轉換頻率及重啟排程仍是必須實測的啟發式。

## 二、已完成的精確原型

`solver/ternary_content_transfer.py` 列出 A 的轉換及完整相關增量向量，
用整數 tuple 作字典 key。對 B 每個轉換查詢

```
ΔP_A = C − P_A − P_B − ΔP_B
```

獨立位移為 1..21。零位移由轉換守恆；其餘由 PACF 反射對稱涵蓋。
字典 key 比較全向量，不是只比較有限位雜湊值；碰撞不會漏解。
相同向量保留一組位置足夠，因為同一轉換方向的新內容相同，可展開性一致。
命中後仍用獨立整數 PACF 與 target/content 驗證。
保留一個代表只足以判定壓縮層存在性；同 PACF 的不同序列可能有不同 lift
結果。若要完整尋找所有可 lift 候選，必須保存同一 key 的全部不同序列，
或串流逐一重新生成；不能因第一個代表 lift 失敗就排除整個 key。

一般兩位置變更 δ_p=α、δ_q=β，對 u>0 的增量為

```
ΔP(u)=α(w_(p+u)+w_(p−u))+β(w_(q+u)+w_(q−u))
      +αβ([p+u=q]+[q+u=p])。
```

這由 P(w+δ) 展開，不能省略最後的二次交叉項。
所有轉換向量的生成及查詢為 O(d³) 算術工作、O(d³) 儲存上界，
相較雙邊轉換的直接笛卡兒積 O(d⁵)。本原型為 Python，尚未接入預設主流程。

`tests/test_ternary_content_transfer.py` 已通過：

- d=3、5 全三值序列的轉換增量對照獨立 PACF。
- L6、L14 各 canonical target，列出所有可行內容的精確壓縮解，對參考候選
  檢查轉換結果，以及「固定內容＋轉換」是否恰覆蓋完整半徑 4 的解。

重播程式 `experiments/benchmark_content_transfer.py` 僅作離線診斷，不用
舊序列初始化正式搜尋，也不寫 L.txt。先測長測中全部能量 ≤12 的 178 個
reference：1.328 秒、0 SAT_COMPRESSED。資料為
`results/L86_content_transfer_probe/report.json`。沒有因此提高發現率的證據。

後續全部 4480 個 reference（能量 ≤24）重播完成：155.201 秒、0 SAT_COMPRESSED，
資料在 `results/L86_content_transfer_all/report.json`。聯合前次全部固定內容

這是壓縮層的有限鄰域排除，不是全域不存在證明。4480 次平均耗時也不能用
178 個較低能量子集的平均耗時代替，兩者內容與可枚舉轉換數不同。

## 三、下一個較大精確鄰域：A、B 各自至多兩交換

令 N₂(a) 是 a 經至多兩次側內交換可達的集合，b 同理。分別生成

```
H_A = { (P_u(1),…,P_u(21)) : u∈N₂(a) }
對每個 v∈N₂(b)，查 C(1..21)−P_v(1..21) 是否在 H_A。
```

兩序列 PACF 和沒有 a、b 之間的乘積，故此分拆是恆等式。它完整搜尋
N₂(a)×N₂(b)，最多可改八個位置。它**不是完整半徑 8**，也不涵蓋
所有半徑 6（例如全部六個位置都在 A 的情形），不能將失敗寫成半徑 8 UNSAT。

單側每個狀態最多 m=binom(43,2)=903 種交換，含零、一、兩交換的有序路徑
最多 1+m+m²=816313。兩側直接配對最多約 6.66×10¹¹；向量字典則只需
生成及查詢約 163 萬條路徑，每條 O(43) 增量/向量工作（雜湊期望複雜度）。
以排序與二分查詢可取得確定的比較複雜度，或保存碰撞鏈並完整比較。

長度 43 的單序列 PACF 在 [−43,43]，21 維 int16 原始向量每側至多約
34.3 MB（十進位），另需位置、索引及雜湊表空間。應用 C 連續陣列，
不把 Python tuple 的實際記憶體誤算成這個數字。只需保存一側表即可串流另一側。
此方法尚未實作／實測，理論工作量下降不等於找到 PQCP 的機率已提高。
同一向量的多個原像也必須保留或可重新生成，才能對 lift 做完整枚舉；
只取一個代表僅保證壓縮層存在性判定。

## 四、執行順序與驗收條件

1. GPU 三值生成加入合法跨內容轉換，獨立整數檢查每個匯出的 best；保留關閉選項。
2. 對保存的少量低能量 reference 實作 C 雙側兩交換匹配，先驗證小型完整枚舉。
3. 同種子、同牆鐘预算比較，記錄精確壓縮工作／秒、可 lift 比率及新完整解。
   能量只是排序啟發式，並非到解的 Hamming 距離；不可据此作無解剪枝。
4. 若 exact jobs 仍為零，再評估不固定內容的 PB/SAT：保留各側
   Σ(p_i−n_i)=43−e−o、n 的合法區間及兩側 Σ(p_i+n_i)=43，
   取代既有固定 p/n 個數等式。所有相關方程不變；逾時仍為 UNKNOWN。
5. 實驗輸出加入 session ID，避免同 seed 覆蓋；排程調整與數學剪枝分開評估。

本次未再增加預設修復工作量，也未將新原型自動啟用。應先驗證上列方法的
實際產出，再投入另一次數小時長測。
