本次實作結果：直接三值支路新增 C 整數延續搜尋，保持既有相關目標與可展開

## 能量 8 不是由已知必要條件導出的下界

對固定 target，a,b 的總和固定；壓縮零位移亦固定。設
r_u=P_a(u)+P_b(u)−C(u)。由 Σ_u P_a(u)=(Σ_i a_i)² 與反射對稱，
且 target 的普通總和條件成立，得到

```
r_0=0，Σ_(u=1)^21 r_u=0。
E=Σ_(u=1)^21 r_u² 為非負偶數，因 r_u²≡r_u (mod 2)。
```

這只能給出非零 E≥2；不能斷言 E=2 一定可由合法三值序列實現。新的實際候選
達到 E=4，已直接證明先前看到的 8 不是此資料表示的普遍數學下界。

## 新方法：整數三值延續搜尋

檔案：`csrc/ternary_anneal.c`、`solver/ternary_native_search.py`。
從本輪新生成的 GPU bests 開始，執行有界三值搜尋；正式路徑不讀取既有解庫
或歷史 reference 初始化。離線診斷可以重播保存的近似候選，但與正式初始化分開。

每次候選只用以下允許移動：

1. 同側交換不同符號，保持每側符號總和及內容。
2. 一側 00→+-，另一側 +-→00，保持每側總和與合計平方和。
   每側新的負號個數 n 必須落在
   max(0,e+o−d)≤n≤min(e,o)，才符合指定 binary 奇偶權重。

移動從目前各符號的位置列表選取，減少原本随机四個位置造成的無效提案。
與 GPU 所記錄的「全部嘗試」相比，native proposals 是有效提案，兩者計數
不能直接當成相同工作量或相同抽樣分布。

### 精確增量與限制

一般 sparse change δ，在獨立位移 u>0：

```
ΔP(u)=Σ_p δ_p(w_(p+u)+w_(p−u)) + Σ_i δ_i δ_(i+u)。
```

對不同位置 p,q 的二次項為
δ_pδ_q([p+u=q]+[q+u=p])。跨側没有交叉乘積。C 以整數計算全部相關
殘差、E、內容及零能量判定；預先建立位移索引，避免每次提案重做取模。
每 1024 次提案以完整 O(d²) 整數 PACF 校核（測試可改成每次都校核）；
回傳的 best 再由 Python 獨立完整重算及內容檢查。任何不一致會丟出錯誤。

退火接受使用 exp(−ΔE/T)，每 8192 次有效提案重複 4→0.15 的溫度排程。
這是導航啟發式；浮點只用於接受概率，不用於相關、可行性、精確命中或無解
剪枝。條件化提案的分布與舊 GPU 分布不同；未聲稱有 Boltzmann 平穩分布，
也沒有使用未校正的詳細平衡作正確性證明。所有接受狀態均符合硬數學限制。
`BOUNDED_MISS` 只是指定工作量未找到精確壓縮解，永遠不是 UNSAT。

算法保留初始與途中最低 E，故延續後的 best E 不高於輸入。這不代表它與解
的 Hamming 距離下降，或可 lift 比率提高。側內交换及合法跨內容转換的連通性
證明沿用 `L86_next_search_design.md`，不构成有限退火找到解的保證。

## 正式整合及使用

GPU batch 後、既有精確修復之前執行整數延續。先各 target 選最佳一個 lane，
再依能量填滿剩餘預算；這是避免小預算全押同 target 的排程選擇，不是剪枝。
預設 4 個 lanes，各最多 131072 有效提案，無須改變原使用方式：

```sh
.venv/bin/python main.py --L 86 --seed 1919810 --torch-device mps --z3 --torch-direct-compression
```

對照舊版本，加 `--torch-direct-compression-native-top 0`；或將
`--torch-direct-compression-native-moves 0`。調大不是已證明更佳的設定。
停止訊號在每個 native reference 之間檢查；一次 C 呼叫以提案數為上限。

新的 `<session>/..._native000000.json` 保存輸入 reference、target、結果與計數。
cycle 增加 `minimum_gpu_compressed_energy`、`native_attempts`、`native_proposals`、
`native_improved`、`native_new_jobs`、`native_seconds`。search_metrics 保存主要計數
及新選項。native_seconds 已包含於 direct_compression，不能重複相加。
`SAT_COMPRESSED` 仍需既有 binary lift 與 independent verifier；此層不直接宣稱 PQCP。

驗證：新增測試對 L6、L14、L46、L86 的每個測試提案（包括被拒絕者）完整
重算 PACF，並核對總和、平方和與內容；小型命中與 literal oracle 對照。
pipeline 測試覆蓋 job 匯出、best 不惡化、0 關閉與取消。
完整可收集回歸為 1128 passed、14 skipped、1 個既有 NumPy warning；沿用
兩個缺失 benchmark 模組測試檔的排除（見 `L86_simulation.md`）。
正式 main.py MPS 短測 exit=0，確實執行 4 個 native reference、524288 次
有效提案、4 個 best 改善，沒有 exact job；資料在 `results/L86_native_main_smoke/`。
指定 12 秒，但有限 block 與收尾完成後為 17.32 秒，不是硬性即時 deadline。

## 近期文獻與本題的差異（本次查閱）

1. Sojoodi、Kotsireas、Afsahi，2026-05-16：
   [Efficient High-Performance Computing Strategies for the Legendre Pairs Search](https://link.springer.com/article/10.1007/s10766-026-00820-y)。
   閱讀出版頁摘要、程式連結，全文訂閱限制。研究 OpenMP/MPI/CUDA 多 GPU，
   說明實作成本對組合搜尋的重要性；其 NVIDIA／Legendre 倍數不適用本機 MPS
   或 PQCP。本文沒有宣稱重現其加速。
2. Lebedev，2026-09 預印本：
   [Quaternary Legendre Pairs of Lengths 42,46,52,58,66,72,and 80](https://arxiv.org/html/2609.04589v1)。
   閱讀 HTML 的框架、討論與證據範圍，提醒完整相關匹配保留同 PACF 的不同
   序列、限制對稱子類的無解不等於全域無解。此文是四相位 Legendre，不能
   把其構造或反射限制直接強加於本題 binary PQCP。
3. Ramos、Hulak、de Queiroz，2026-07 預印本：
   [Multiplier obstructions for Legendre pairs of length 333](https://arxiv.org/html/2607.20765v1)。
   閱讀共同固定乘子與壓縮的定義、摘要及限制。其子群排除針對 333 的指定
   對稱類，不能移用為 86 的排除定理。本題共同固定 q 時目標支撐 {±k} 也
   必須不變；k=1 或 2 均迫使 q=±1 mod86，因此大乘法軌道限制不可直接套用。
4. [2026 ICMS SAT 摘要](https://icms-conference.org/2026/abstracts/Andraschko.pdf)
   仍支持先求三值壓縮後 lift 的架構，目標是 PG 零旁瓣。此輪沒有把摘要中的
   求解器收益當作本題實測，也沒有採用未核實的全域存在性結論。

新增 C 搜尋主要是現有數學允許移動的高效實作與導航配置，不宣稱首次提出
退火或新的存在性定理。下一輪的關鍵指標仍是 exact jobs／秒、lift 結果及
完整非等價新解；僅低能量改善還不足證明研究目標已達成。
