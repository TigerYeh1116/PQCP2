二、嚴格的數學定義

原始儲存使用 A_i、B_i∈{0,1}；數學推導使用 x_i=(-1)^(A_i)、y_i=(-1)^(B_i)∈{−1,+1}。索引皆取模 L。

定義週期自相關：
    P_x(u)=Σ_(i=0)^(L−1) x_i x_((i+u) mod L)
    S(u)=P_x(u)+P_y(u)。

本題要求：
    S(0)=2L；
    在 u=1,...,L−1 中，恰好兩個位置非零，每個非零值的絕對值皆為 4。

由週期自相關的反射對稱 S(u)=S(L−u)，偶數長度的目標可寫為：
    T(0)=2L；
    T(k)=T(L−k)=4η，η∈{−1,+1}，1≤k<L/2；
    其餘 T(u)=0，特別是 T(L/2)=0。

注意：計算的是兩個實際位移索引，而不是兩個對稱軌道；它們構成一個反射軌道，且兩個值同號。「最大旁瓣不超過 4」比原題弱，不能取代本題。

主要核對程式：
    solver/problem.py
    solver/correlation.py
    solver/objective.py
    solver/verifier.py

獨立 verifier 會從二元序列重新計算完整相關函數，而非信任 GPU 的低能量、壓縮層 SAT 或 Z3 的回傳標籤。正式結果入口是 solver/search_runner.py 的 append_verified_solution_if_new。

三、值得詳細推導的必要條件

（一）普通總和與交替總和

令 X=Σx_i、Y=Σy_i、U=Σ(-1)^i x_i、V=Σ(-1)^i y_i。
對偶數 L，交換求和或使用傅立葉的零頻與半頻特徵，可得：
    X²+Y²=2L+8η；
    U²+V²=2L+8η(-1)^k。

L86 時，η=+1 給出 (|X|/2,|Y|/2)=(6,3) 或其交換；η=−1 時為 (5,4) 或其交換。交替總和受第二式約束。它們能限制每條序列偶位、奇位的負號個數，並不充分保證 PQCP。

現有 canonical target/content profiles（bit=1 即符號 −1）：
    k=1, η=−1：A 偶位16、奇位22；B 偶位18、奇位21。
    k=1, η=+1：A 偶位16、奇位21；B 偶位18、奇位22。
    k=2, η=−1：A 偶位17、奇位21；B 偶位17、奇位22。
    k=2, η=+1：A 偶位17、奇位20；B 偶位17、奇位23。

請閱讀 solver/target_profiles.py，說明整數平方和、奇偶權重及對稱正規化如何導出這些分支；不能只列數字而沒有理由。

（二）傅立葉功率譜

採未正規化 DFT，Wiener–Khinchin 關係給出：
    |X̂(f)|²+|Ŷ(f)|²=DFT(T)(f)
                       =2L+8η cos(2πfk/L)。

因單側功率譜非負，每側皆不得超過右端，這是必要條件。請區分：精確必要條件、浮點數計算時的誤差處理、以及將違反量加入連續 loss 的軟懲罰。不能把近似數值測試直接宣稱為嚴格無解證明。

（三）群作用与等價

現有正式解庫的 canonical key 使用：各側獨立循環旋轉、反轉、全部取負；A/B 交換；以及兩側共同使用同一個可逆抽取 i↦qi mod L，gcd(q,L)=1。
對 L86，非零目標位移的單位群軌道可依奇偶分為 k=1 與 k=2 代表。
不可對 A、B 使用不同 q 後仍宣稱保留配對目標。相同 PACF 也不代表序列在上述群作用下等價。

另有可推導的交替調變：同時 x'_i=(-1)^i x_i、y'_i=(-1)^i y_i，則 S'(u)=(-1)^u S(u)。它能對應奇數 k 的兩種 η，但目前沒有納入正式解庫的等價定義；不能在報告中寫成已採用的去重方法。

參考：solver/solution_equivalence.py、solver/compressed_equivalence.py、docs/solution_equivalence.md。

四、序列壓縮與 L86 的三值表示

一般 L=md 的壓縮定義：
    c_r=Σ_(q=0)^(m−1) x_(r+qd)，r=0,...,d−1。
其相關滿足：
    P_c(r)=Σ_(q=0)^(m−1) P_x(r+qd)。

報告應從求和索引分組推導這個恆等式，並說明它為何只是對原問題的必要投影：符合壓縮目標不一定能展開成符合全部相關條件的二元解。

L86=2×43。使用正規化三值序列：
    a_i=(x_i+x_(i+43))/2，b_i=(y_i+y_(i+43))/2；
    a_i,b_i∈{−1,0,+1}。
其配對相關 C(r) 為：
    C(r)=P_a(r)+P_b(r)=[T(r)+T(r+43)]/4；
    C(0)=43，C(±k mod 43)=η，其餘為 0。

所以兩條三值序列合計恰有 43 個非零位置、43 個零位置。
程式某些模組使用未正規化 c_i=x_i+x_(i+43)∈{−2,0,2}，不能把兩套表示的因子 2、4 混用。

設一側對應的 binary 偶位、奇位 bit=1 個數為 e,o，三值 −1、0、+1 個數為 n,z,p，則：
    z=e+o−2n；p=43−e−o+n；
    max(0,e+o−43)≤n≤min(e,o)。
這些條件對「可按指定奇偶權重展開」是充分必要的，但不是對「可展開為 PQCP」充分。

43 是質數，因此標準因數壓縮 86→43 之後没有非平凡下一層。不可把其他複合長度的多層壓縮加速直接搬到 86。

主要程式：solver/structured_energy.py、solver/compressed_fkm.py、solver/torch_compressed_search.py、solver/compressed_pairing.py、solver/compressed_completion.py。

五、精確展開：方向變數、負週期相關與 GF(2)

對 L=2d、d 為奇數，定義未正規化 c_i=x_i+x_(i+d)，h_i=(x_i−x_(i+d))/2。
c_i≠0 的位置已決定兩個 binary bits；c_i=0 才需要決定方向 h_i=±1。
精確壓縮配對滿足 T(d)=0 時，兩側共有 d 個方向變數，L86 即 43 個。

令 N_h 是負週期（negacyclic）相關，越過長度 d 的項需變號，則：
    P_x(u)=P_c(u)/2+2N_h(u)；
    P_x(u+d)=P_c(u)/2−2N_h(u)。
故剩餘精確方向方程為：
    N_hA(u)+N_hB(u)=[T(u)−T(u+d)]/4。

對奇數 d，N(d−u)=−N(u)，獨立方程可取 u=1,...,(d−1)/2，L86 為 21 個。
注意 N 不能當作普通 periodic PACF。

將方向寫成 h_i=(-1)^b_i，可把每個整數方程的必要奇偶條件转成 GF(2) 線性方程。高斯消去若矛盾，可排除該固定壓縮工作；若 rank=r，可將方向以 d−r 個自由變數表示，但仍必須滿足原本完整整數方程及 binary 奇偶權重。
不能把「GF(2) 一致」寫成存在完整解；rank 也不是固定為 21。

主要程式：solver/orientation_gf2.py、solver/orientation_search.py、solver/compressed_lift.py、solver/staged_completion.py。
精確公式與推導詳見 docs/odd_half_gf2_lift.md；建議把推導整理成報告的重要章節。

六、目前整體程式架構

入口是 main.py。簡化流程為：
    數學必要條件與目標分支
        → GPU 批次連續鬆弛／量化／離散 polish，並搭配 CPU C 搜尋
        → 壓縮簽章配對或直接三值搜尋
        → 精確壓縮候選
        → 背景 GF(2)／方向搜尋／Z3 lift
        → 獨立完整相關驗證
        → 等價去重與正式解庫寫入。

這是一個多支路、有界工作量的混合搜尋，不是單一窮舉演算法，也不是整個 L86 空間的完整 SAT 證明。

程式主要角色：
    main.py：CLI、互動啟動、資源選擇、後端與 completion bridge。
    solver/torch_hybrid_runner.py：GPU formation、polish、direct compression 與 CPU 搜尋協調。
    solver/torch_relaxation.py、torch_population.py、torch_search.py：連續表示與族群搜尋，具體角色以函式呼叫核實。
    solver/torch_polish.py、torch_alternating.py：離散與壓縮／方向交替 polish。
    solver/c_backend.py、csrc/：C 搜尋及本地加速核心。
    solver/compressed_completion.py：壓縮工作與匹配池。
    solver/staged_completion.py：分段求解、逾時工作保存與接續。
    solver/search_metrics.py：計數與階段時間；本身不證明搜尋品質。

請特別區分三類量：
    1. pqcp_objective：完整 profile 的精確整數評分，零值对应本題要求。
    2. 三值壓縮能量：Σ_(u=1)^21 (P_a(u)+P_b(u)−C(u))²，零值僅代表壓縮層成立。
    3. 連續 loss：用於鬆弛導航，可含二元懲罰、內容約束、折疊殘差及可選數學項；其權重、參數屬搜尋設計。
壓縮能量 6、8 與完整 objective 6、8 不能互相比較；低能量也不是到解的 Hamming 距離。

七、近期已實作的數學搜尋改進

（一）固定內容半徑 4 精確修復

在每側三種符號個數固定時，任一 Hamming 距離≤4 的候選皆可由兩側合計至多兩次交換產生，反之亦然。
證明：把每個改動位置畫為「舊符號→新符號」邊；內容守恆使三頂點有向圖平衡，分解為 2-cycle 或 3-cycle。至多四條邊只能是一個 2-cycle、一個 3-cycle 或兩個 2-cycles，皆可用至多兩次交換實現。
此結論依賴三值字母表及固定內容，不能任意推广。

交換 p,q，t=w_q−w_p，u>0 的精確相關增量為：
    ΔP(u)=t[w_(p+u)+w_(p−u)−w_(q+u)−w_(q−u)]
           −t²([p+u=q]+[q+u=p])。
第二次交換須使用第一次交換後的序列計算；不能忽略二次項。

實作：csrc/ternary_repair.c、solver/ternary_repair_native.py。
另有 solver/compressed_repair.py 的 Z3 偽布林半徑修復原型，不等於主流程每輪都執行它。

（二）跨內容轉換與連通性

在保持各側符號總和及兩側總平方和下，允许：
    A 的 00→(+1,−1)，B 的 (+1,−1)→00，或反向，並允许正負位置互換。
每次必須檢查新內容仍能按指定 binary 奇偶權重展開。

對固定長度與總和，內容變化必為 (Δn,Δz,Δp)=(t,−2t,t)。總平方和固定使 t_A+t_B=0。在總改動≤4 時，跨內容只能是 t_A=±1、t_B=∓1 的上述轉換。
因此固定內容修復與跨內容轉換的聯集，覆蓋同一 target 奇偶權重下全部合法三值半徑 4 候選。

可行 n_A 是整數區間，n_B 由 n_A+n_B 的固定值決定。側內交換連通同一內容的所有排列，跨內容轉換連接相鄰可行 n_A，因此允許移動的狀態圖連通。
這不表示只接受降能量移動的軌跡連通，也不表示有限退火一定收斂至解。

實作：solver/ternary_content_transfer.py；GPU 提案位於 solver/torch_compressed_search.py 的 content_transfer_trials。
目前主流程預設每 4 個三值搜尋步改用跨內容提案，並對每輪最多 8 個低能量候選做跨內容精確修復。這些頻率與候選數是可調啟發式。

（三）雙側兩交換的精確相關向量匹配

令 N₂(a) 為一側至多兩次交換可達的集合，搜尋 N₂(a)×N₂(b)。對 21 個獨立位移建立 P_u 向量，再對另一側查找：
    P_u=C−P_v。
因配對 PACF 只是兩側相加，沒有跨側乘積，此拆分精確。

目前 C 實作採排序與二分查詢，不是只存雜湊摘要；相同完整向量的不同序列也會保留並逐一交接。若輸出上限截斷，會明確標示未完整枚舉。
此鄰域每側最多改四個位置，總共最多八個，但不是完整半徑 8，也不覆蓋所有半徑 6 候選。

單側 d=43，最多 m=binom(43,2)=903 種交換，零、一、兩交換路徑上界為 1+m+m²=816313。這是含重複終點的路徑上界，不是不同候選的精確個數。
用向量匹配避免直接掃描兩側路徑的笛卡兒積；實作的排序／查詢複雜度應依程式分析，不能把雜湊的期望 O(M) 當成目前排序版本的確定界。

實作：csrc/ternary_mitm.c、solver/ternary_mitm.py、solver/compressed_repair_pipeline.py。
目前預設每輪對 1 個 reference 做 MITM，每個 reference 最多匯出 32 個不同壓縮序列對，再交由既有等價去重與 lift。

八、狀態與正確性敘述

    SAT_COMPRESSED：符合壓縮相關目標，不等於完整 PQCP。
    UNSAT_LOCAL：只排除特定 reference、固定內容及指定半徑。
    UNSAT_TRANSFER：只排除該 reference 的跨內容轉換類別。
    UNSAT_NEIGHBORHOOD：只排除 N₂(A)×N₂(B)。
    SAT_COMPLETE：MITM 所定義鄰域的不同壓縮配對已全部枚舉。
    SAT_TRUNCATED：已達輸出上限且存在更多不同配對，不能宣稱完整。
    UNKNOWN：逾時／工作預算用完，不是 UNSAT。

即使壓縮匹配完整，有限輸出、queue admission、lift 時間限制及重啟策略仍使整体為有界搜尋。
每個無解結論都必須寫清楚量詞與搜尋集合，不能省略「固定工作」「指定鄰域」等限制。

十、環境、啟動與保存

本機專案以 Apple Silicon、32 GiB 統一記憶體為使用情境；使用者與先前環境檢查記錄為 M6。硬體型號及核心數若要列入正式報告，請依本機系統查詢重新確認。
主要環境為 Python 3.9.6、PyTorch 2.8.0、z3-solver 5.1.0.0、mpmath 1.3.0、pytest 8.4.2；以 requirements.txt 與實際 .venv 為準。C 使用本機 cc 編譯，MPS 在某些工具沙箱內不可用，不能直接由沙箱內 false 推論本機沒有 GPU 支援。

目前完整新支路啟動：
    .venv/bin/python main.py --L 86 --seed 123 --torch-device mps --z3 --torch-direct-compression
可加 --hours 1 指定一小時，不加時間參數則持續搜尋。
互動模式選 L86、Z3，並啟用直接三值壓縮搜尋即可。注意直接壓縮支路本身仍須明確啟用，不能把所有可選功能寫成全域預設一直運行。

新版本逐輪資料放在 results/direct_compression/<session>/，避免同 seed 覆蓋。舊版本的平面 cycle／repair 檔曾有同 seed 覆蓋問題，部分歷史逐輪資料不可當作完整保存；独立命名的 search_metrics 仍可查。

曾做 GPU batch、FP32／FP16、矩陣封裝等實驗，尚無證據顯示把運算交给 Apple Neural Engine／神經網路加速器。不能把晶片宣傳功能、MPS 可用或較大 batch 寫成已使用神經引擎。
硬體調整與數學搜尋改進須分開評估，參考 docs/hardware_resources.md、docs/gpu_neural_accelerators.md。

1. Andraschko、Kotsireas、Kreuzer，Computing Periodic Golay Pairs Using SAT Solvers，2026 ICMS：
   https://icms-conference.org/2026/abstracts/Andraschko.pdf

   https://arxiv.org/abs/2408.15611
   前次核對版本頁為 2024 首稿、2025-03-16 v3。研究 compression、multilevel compression、orderly generation。引用時重新確認正式出版資訊，不把 arXiv 修訂日期當作期刊出版日期。

3. Perera、Kotsireas，A low-complexity algorithm to search for Legendre pairs，2025：

   前面主要讀出版頁摘要；不能聲稱已重現其完整演算法或速度收益。
